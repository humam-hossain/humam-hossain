# Plan 03-01: Curated Projects Configuration & Batched GraphQL Query Engine

## Executive Summary

Establish the data acquisition and configuration foundation for the Open Source Projects Dashboard as a tracer plan. Plan 03-01 introduces a dedicated, human-editable repository curation file (`config/projects.json`) seeded with 4 starter repositories (`linux_shell_scripting`, `Python`, `nn`, `antigravity-cli-statusline`) per D-07, D-08, D-09, and D-10. It builds a robust config loader and schema normalizer in `scripts/update_profile.py`, a batched GraphQL query engine using indexed aliases (`repo_0`, `repo_1`) to bypass GraphQL identifier syntax restrictions while fetching all metrics in a single API call per D-16, a smart fallback description resolver per D-14, and static offline fixture fallback per D-18. It initializes `tests/fixtures/graphql_projects.json` and `tests/test_projects.py` to guarantee 100% offline test coverage under full network isolation.

## Threat Model (ASVS Level 1)

<threat_model>
### STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation Strategy |
|-----------|----------|-----------|-------------|---------------------|
| T-03-01 | Injection | `scripts/update_profile.py:build_batched_projects_query` | GraphQL syntax injection or malformed queries caused by repository names containing hyphens (`-`), periods (`.`), or starting with numbers. | Use indexed numeric aliases (`repo_0`, `repo_1`, `repo_2`, `repo_3`) strictly. Never interpolate unescaped repo names as GraphQL alias identifiers (conforms to GraphQL Spec §2.7). |
| T-03-02 | Denial of Service | `scripts/update_profile.py:fetch_project_telemetry` | Rate-limit exhaustion from querying multiple repositories sequentially. | Batch all curated repositories into a single consolidated GraphQL query using aliases, consuming exactly 1 API quota point per D-16. |
| T-03-03 | Denial of Service | `scripts/update_profile.py:fetch_project_telemetry` | Network outages, API downtime, or missing `GITHUB_TOKEN` halting profile update pipeline. | Multi-tier fallback per D-18: try live GraphQL -> on error fall back to `cache['project_metrics']` -> on empty cache fall back to static fixtures with `log_warn()`, exiting code 0. |
| T-03-04 | Information Disclosure | `scripts/update_profile.py` | Accidental exposure of API tokens in GraphQL query strings, cache payloads, or debug logs. | GraphQL headers use `Authorization: Bearer <token>` in memory only; tokens are never logged, cached, or written to disk. |
| T-03-05 | Tampering / Schema Poisoning | `config/projects.json` | Malformed JSON or invalid schema types causing updater crash. | Wrap JSON loading in `try/except` with schema validation; normalize both plain strings and dictionaries to standard internal schema; default missing owner to `"humam-hossain"`. |
</threat_model>
