# Plan 02-03: Parameterized SVG Re-rendering & Idempotent Update Integration

## Executive Summary

Integrate the dynamic metrics engine with the vector graphic generation pipeline to produce live, updated hero cards (`assets/hero.svg`). Plan 02-03 parameterizes `scripts/generate_hero.py` to accept dynamic uptime, LOC additions, and LOC deletions while preserving all DOM update hooks (`val-uptime`, `val-loc-add`, `val-loc-del`) and default values per Requirement HERO-04 and HERO-05. It implements strict `xml.etree.ElementTree` validation to prevent XML corruption, idempotent file writing to prevent git diff churn per Requirement AUTO-01, and executes the complete pipeline end-to-end with 100% test suite pass rate across Phase 1 and Phase 2.

### STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation Strategy |
|-----------|----------|-----------|-------------|---------------------|
| T-02-10 | Injection | `scripts/generate_hero.py` | Special characters in dynamic telemetry (`<`, `>`, `&`, quotes) corrupt SVG XML or cause parser injection. | Injected telemetry values passed through `xml.sax.saxutils.escape()` prior to string interpolation; output strictly validated via `ET.fromstring()` per D-10. |
| T-02-11 | Repudiation / Churn | `scripts/update_profile.py` | Repeated daily runs overwrite `assets/hero.svg` and update file mtime even when metrics are unchanged, creating noisy git commits. | `write_svg_idempotent()` reads existing file content and skips writing if byte-identical per D-11. |
| T-02-12 | Regression | DOM Structure | Generator parameterization changes layout geometry or removes DOM IDs (`val-uptime`, `val-loc-add`, `val-loc-del`), breaking future phase extensions. | Regression tests in `tests/test_tokens.py` and `tests/test_update_profile.py` assert exact DOM IDs and geometry tokens. |
</threat_model>

</read_first>

<action>
1. In `scripts/update_profile.py`, implement `write_svg_idempotent(output_path: Path, new_svg: str) -> bool` per D-10, D-11:
   - Validates XML with `ET.fromstring(new_svg)` (T-02-10).
   - If `output_path.exists()` and `output_path.read_text(encoding="utf-8") == new_svg`, logs `[INFO] {output_path.name} is already up to date (idempotent skip)` and returns `False` (T-02-11).
   - Otherwise, ensures parent directory exists, writes UTF-8 content to `output_path`, logs `[OK] Updated {output_path.name}`, and returns `True`.
2. Connect end-to-end pipeline in `scripts/update_profile.py`:
   - Resolve credentials (`get_github_token`).
   - Load theme config (`config/terminal_theme.json`) and cache (`data/cache.json`).
   - Determine baseline start date (override $\rightarrow$ cache $\rightarrow$ GraphQL discovery $\rightarrow$ createdAt).
   - Calculate elapsed calendar coding uptime in UTC (`compute_calendar_diff`) and format (`format_uptime_neofetch`).
   - Enumerate repos and incrementally aggregate LOC additions/deletions (`aggregate_loc`) and format (`format_loc_counts`).
   - Generate refreshed SVG string via `generate_svg(uptime=uptime_str, loc_add=loc_add_str, loc_del=loc_del_str)`.
   - Write output via `write_svg_idempotent(HERO_SVG_PATH, svg_content)`.
   - Save updated state to `data/cache.json`.
   - Log completion: `log_ok("Profile telemetry refresh complete.")`.
3. Add tests in `tests/test_update_profile.py`:
   - `test_idempotent_write`: verifies first write returns `True` and creates file, while identical subsequent write returns `False`.
   - `test_full_pipeline_offline_execution`: executes full `update_profile.main()` offline with temporary output path and asserts clean exit code 0 and generated valid SVG.
4. Execute `python3 scripts/update_profile.py` locally to refresh `assets/hero.svg`.
5. Run entire test suite across all test files (`pytest tests/ -v`).
</action>
