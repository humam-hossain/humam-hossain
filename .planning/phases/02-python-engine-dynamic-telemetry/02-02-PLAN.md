# Plan 02-02: Coding Uptime Engine & Incremental LOC Aggregator

## Executive Summary

Implement dynamic metrics calculation for the profile engine: real-time coding uptime and aggregate lines of code (LOC). Plan 02-02 delivers calendar-accurate UTC date math matching `relativedelta` boundary cases, Neofetch-style uptime string formatting with stable 3-unit width per Requirement HERO-04, and owned public non-fork repository LOC aggregation (additions `++` and deletions `--`) with incremental caching in `data/cache.json` per Requirement HERO-05. It introduces configurable repository exclusions in `config/terminal_theme.json`, batch-safe commit pagination ($\le 50$) preventing HTTP 502 timeouts, and unit test coverage in `tests/test_update_profile.py`.

## Threat Model (ASVS Level 1)

<threat_model>
### STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation Strategy |
|-----------|----------|-----------|-------------|---------------------|
| T-02-06 | Tampering | `data/cache.json` | Corrupted, unreadable, or invalid JSON cache file crashes update script during execution. | `load_cache()` catches `json.JSONDecodeError` and `OSError`, emits `[WARN]`, and falls back to a clean default state with known baseline values. |
| T-02-07 | Denial of Service | `scripts/update_profile.py` | Querying 100 commits or unbatched repositories in GraphQL exhausts git diff backend timeouts, causing HTTP 502 Bad Gateway. | Enumerate repos first; fetch commit history in batches strictly $\le 50$ commits per page per D-15. Incremental caching bypasses queries for repos whose `pushedAt` is unchanged per D-07. |
| T-02-08 | Data Integrity | `scripts/update_profile.py` | Naive calendar arithmetic drifts on month ends (e.g. Jan 31 $\rightarrow$ Feb 28) and leap years, producing inaccurate uptime figures. | Verified `_add_calendar_months()` and `compute_calendar_diff()` algorithm clamps to month length and exactly mirrors `dateutil.relativedelta` per D-03. |
| T-02-09 | Denial of Service | GitHub GraphQL Quota | Re-querying lifetime commit history on every run consumes the 5,000 hourly point quota. | First-commit baseline timestamp is cached permanently in `data/cache.json` (D-02); future executions perform 0 historical queries. |
</threat_model>

### Task 02-02-01: Extend Theme Config & Implement Calendar-Accurate Coding Uptime Engine (`config/terminal_theme.json`, `scripts/update_profile.py`, `tests/test_update_profile.py`)

- .planning/phases/02-python-engine-dynamic-telemetry/02-RESEARCH.md (Section 3)
- config/terminal_theme.json

<action>
1. Extend `config/terminal_theme.json` by adding a `"telemetry"` configuration block per D-01, D-06:
   ```json
   "telemetry": {
     "exclude_repos": [],
     "baseline_override_date": null
   }
   ```
2. In `scripts/update_profile.py`, implement UTC calendar date math per D-03:
   - `_add_calendar_months(dt: datetime.datetime, months: int) -> datetime.datetime`: adds calendar months while clamping to the target month's maximum days via `calendar.monthrange`.
   - `compute_calendar_diff(start: datetime.datetime, end: datetime.datetime) -> tuple[int, int, int]`: computes exact (years, months, days) elapsed between two UTC datetimes. Returns `(0, 0, 0)` if `end < start`.
   - Enforce `datetime.timezone.utc` on all datetime operations; reject naive datetimes.
3. In `scripts/update_profile.py`, implement Neofetch uptime formatting per D-04:
   - `format_uptime_neofetch(years: int, months: int, days: int) -> str`: produces `X yrs, Y mos, Z days` with intelligent pluralization (`1 yr` / `2 yrs`, `1 mo` / `3 mos`, `1 day` / `12 days`) while always displaying all 3 units (e.g. `4 yrs, 0 mos, 12 days`).
4. In `scripts/update_profile.py`, implement baseline discovery precedence per D-01, D-02:
   - Priority 1: `telemetry.baseline_override_date` from `config/terminal_theme.json` if non-null.
   - Priority 2: `baseline.first_commit_date` in `data/cache.json` if present.
   - Priority 3: GraphQL discovery query querying `viewer.contributionsCollection(from, to)` for earliest year from `contributionYears`, falling back to `viewer.createdAt`.
5. Add unit tests in `tests/test_update_profile.py`:
   - `test_calendar_uptime_math`: tests standard date differences (`2020-09-18` to `2026-11-07`), leap year edge cases (`2024-02-29` to `2025-02-28`), month boundary clamping (`2020-01-31` to `2020-02-29`), and pluralization variations (`1 yr, 1 mo, 1 day` vs `2 yrs, 0 mos, 15 days`).
   - `test_baseline_discovery_precedence`: verifies override > cache > GraphQL fallback.
</action>

<verify>

  <fails_when>Uptime tests fail, calendar math drifts on leap year/month boundaries, or pluralization is incorrect</fails_when>
</verify>

### Task 02-02-02: Implement Incremental LOC Aggregator & Persistent Cache Management (`data/cache.json`, `scripts/update_profile.py`, `tests/test_update_profile.py`)

<read_first>
- .planning/phases/02-python-engine-dynamic-telemetry/02-CONTEXT.md (D-02, D-05, D-06, D-07, D-08, D-15)
- .planning/phases/02-python-engine-dynamic-telemetry/02-PATTERNS.md (Section 2.4, Section 3.6)
- .planning/phases/02-python-engine-dynamic-telemetry/02-RESEARCH.md (Section 2, Section 4)
</read_first>

<action>
1. Create `data/cache.json` pre-seeded with baseline start date and initial repository metrics per D-02, D-07:
   - `baseline.first_commit_date`: `"2020-09-18T07:00:00Z"`
   - `baseline.account_created_at`: `"2020-06-12T11:30:35Z"`
   - `baseline.source`: `"contributionsCollection"`
   - `repositories`: dictionary mapping repository names to `{"pushed_at": str, "additions": int, "deletions": int}`
   - `totals`: `{"additions": int, "deletions": int, "last_updated": str}`
2. In `scripts/update_profile.py`, implement cache persistence helpers:
   - `load_cache(cache_path: Path) -> dict`: safely loads JSON with default fallback on missing or corrupted file (T-02-06).
   - `save_cache(cache_path: Path, data: dict) -> None`: writes formatted JSON with 2-space indentation.
3. In `scripts/update_profile.py`, implement LOC formatting per D-08:
   - `format_loc_counts(additions: int, deletions: int) -> tuple[str, str]`: returns `(f"++{additions:,}", f"--{deletions:,}")`.
4. In `scripts/update_profile.py`, implement repository enumeration and incremental LOC aggregation per D-05, D-06, D-07, D-15:
   - Query GraphQL for user's owned non-fork repositories (`ownerAffiliations: [OWNER]`, `isFork: false`), including archived repositories per D-05.
   - Filter out any repository matching names in `telemetry.exclude_repos` per D-06.
   - Compare `repo.pushedAt` with `cache["repositories"][repo_name]["pushed_at"]`.
   - On match (cache hit): retain cached additions and deletions without querying commits (0 API calls).
   - On mismatch or new repo (cache miss): query commit history additions and deletions in batches strictly $\le 50$ commits per page (`first: 50`) per D-15 to prevent HTTP 502 Bad Gateway timeouts.
   - Sum additions and deletions across all active repositories to compute overall totals.
5. Add unit tests in `tests/test_update_profile.py`:
   - `test_loc_formatting`: verifies comma formatting (`++320,410` / `--85,240`) and zero counts (`++0` / `--0`).
   - `test_cache_lifecycle`: tests loading default, writing updates, and reloading modified cache.
   - `test_incremental_cache_hit_skip`: tests that unchanged `pushed_at` avoids commit queries while advanced `pushed_at` recalculates.
   - `test_exclude_repos_filtering`: tests that excluded repositories are omitted from total LOC summation.
</action>

<verify>
  <automated>pytest tests/test_update_profile.py -k "test_loc_formatting or test_cache_lifecycle or test_incremental or test_exclude_repos" -v</automated>
  <fails_when>LOC tests fail, cache loading fails, or excluded repositories are included in LOC sum</fails_when>
</verify>

<done>
`data/cache.json` exists and is tracked; `scripts/update_profile.py` implements cache management, incremental LOC calculation, and comma formatting; all LOC and cache unit tests pass.
</done>
