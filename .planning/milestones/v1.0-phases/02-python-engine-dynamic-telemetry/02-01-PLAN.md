# Plan 02-01: Update Engine Core, Auth, Retries & Offline Fallback

## Executive Summary

Establish the core execution scaffold for the profile automation engine (`scripts/update_profile.py`) as a tracer plan. Plan 02-01 delivers pure standard library multi-source credential resolution (`GITHUB_TOKEN`, `GH_TOKEN`, local `.env`), resilient GitHub GraphQL transport with exponential backoff and `Retry-After` header handling, terminal-styled ANSI logging matching the workstation theme, and graceful offline fallback when unauthenticated. It builds Wave 0 offline test fixtures and the `tests/test_update_profile.py` test suite to enforce 100% network isolation and zero-dependency compliance per Requirement AUTO-01.

---

## Threat Model (ASVS Level 1)

<threat_model>
### STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation Strategy |
|-----------|----------|-----------|-------------|---------------------|
| T-02-01 | Information Disclosure | `scripts/update_profile.py` | Accidental leakage of `GITHUB_TOKEN` or personal access token to stdout, error traces, or git commits. | Multi-source resolver reads env/.env in memory only. CLI logging never echoes token values; sanitizes error traces to omit `Authorization` headers. |
| T-02-02 | Denial of Service | `scripts/update_profile.py` | Rate-limit exhaustion or secondary limits on GitHub GraphQL API causing automated runner failure. | Exponential backoff (1s, 2s, 4s) with up to 3 retries; parses `Retry-After` and `X-RateLimit-Remaining` headers per D-15. |
| T-02-03 | Denial of Service | `scripts/update_profile.py` | Local development or unauthenticated runner crashes on missing token. | Graceful offline fallback per D-14: emits `[WARN]` and exits code 0 without raising unhandled exceptions. |
| T-02-04 | Injection | `scripts/update_profile.py` | GraphQL query injection via unescaped string formatting in query payloads. | All variables serialized via `json.dumps()` into payload parameters rather than raw string interpolation. |
| T-02-05 | Supply Chain (SC) | Runtime Environment | External dependency poisoning via third-party HTTP or dotenv libraries. | Pure Python standard library implementation (`urllib.request`, `json`, `os`, `pathlib`); zero pip runtime packages. |
</threat_model>

<action>

2. Implement terminal-styled ANSI logging helpers per D-12:
   - `ANSI_BLUE` (`#58a6ff` -> `\033[38;2;88;166;255m`) for `log_info(msg)`
   - `ANSI_GREEN` (`#3fb950` -> `\033[38;2;63;185;80m`) for `log_ok(msg)`
   - `ANSI_AMBER` (`#ffa657` -> `\033[38;2;255;166;87m`) for `log_warn(msg)`
   - `ANSI_RED` (`#f85149` -> `\033[38;2;248;81;73m`) for `log_err(msg)`
3. Implement `get_github_token(root_dir: Path) -> str | None` per D-13:
   - Checks `os.environ.get("GITHUB_TOKEN")`.
   - Checks `os.environ.get("GH_TOKEN")`.
   - Parses local `.env` line by line for `GITHUB_TOKEN=` or `GH_TOKEN=` using standard library string parsing (zero external dotenv library).
   - Never exposes token strings in logs or debug statements (T-02-01).
4. Implement `execute_graphql(query: str, variables: dict | None = None, token: str | None = None, max_retries: int = 3) -> dict` per D-15:
   - Uses `urllib.request.Request` with `Authorization: Bearer <token>`, `Content-Type: application/json`, and `User-Agent: humam-hossain-profile-updater`.
   - Implements exponential backoff (`delay = 1.0`, doubles on retry) for retryable HTTP codes (`429`, `500`, `502`, `503`, `504`) and network errors (`URLError`, `TimeoutError`, `ConnectionError`).
   - Checks and respects `Retry-After` header when HTTP 429 occurs.
   - Logs warning if `X-RateLimit-Remaining` falls below 100.
   - Raises `RuntimeError` on persistent failure after max retries or on 401/404 non-retryable errors.
</action>
