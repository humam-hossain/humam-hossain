# Plan 04-02: Streak Telemetry Math & Terminal Metrics SVG Generator

## Executive Summary

Implement the commit streak calculation engine and the standalone SVG graphics generator (`scripts/generate_metrics.py`) rendering `assets/metrics.svg` per METRIC-02. Plan 04-02 introduces `compute_streaks_from_calendar()` in `scripts/update_profile.py` with the GitHub today-grace-period per D-05 (keeping streaks active until end-of-day UTC if pushed yesterday) and standby handling for 0-day periods (`[standby]` in `#8b949e`) per D-06. It builds `scripts/generate_metrics.py` as an independent generator producing a self-contained 850px-wide SVG terminal window (`viewBox="0 0 850 340"`) featuring macOS traffic lights, window title `stats — zsh`, prompt line `humam@workstation:~$ git status --telemetry`, a two-column split layout with 3 streak mini-panels on the left and vector `<rect>` progress tracks on the right per D-01, D-02, D-03, D-04, D-07, and D-11. Strict standard library XML validation (`xml.etree.ElementTree`) ensures 100% valid document output.

## Threat Model (ASVS Level 1)

<threat_model>
### STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation Strategy |
|-----------|----------|-----------|-------------|---------------------|
| T-04-05 | Tampering / Logic Flaw | `scripts/update_profile.py:compute_streaks_from_calendar` | Premature streak reset to 0 when user has not yet committed on the current UTC calendar day but pushed yesterday. | Implement today-grace-period per D-05: if `today_utc` count is 0, check `yesterday_utc`; if > 0, count streak consecutively backwards from yesterday. |

| T-04-07 | Spoofing / Layout Distortion | `scripts/generate_metrics.py:generate_metrics_svg` | Unicode font variation across platforms (macOS SFMono vs Windows Consolas) distorting progress track widths. | Render progress tracks as SVG vector `<rect>` elements (`rx="3"`, width derived from percentage) instead of Unicode block glyphs per D-07. |
| T-04-08 | Denial of Service | `scripts/update_profile.py:fetch_streak_telemetry` | Rate limit or GraphQL network failure crashing update pipeline during streak collection. | Multi-tier fallback per D-22: try live GraphQL -> on error fall back to `cache['streak_metrics']` -> on missing cache fall back to `DEFAULT_STREAK_FIXTURES`. |
</threat_model>

### Task 04-02-01: Implement Streak Calculation & GraphQL Calendar Fetcher (`scripts/update_profile.py`, `tests/test_metrics.py`)

<read_first>
- scripts/update_profile.py (Existing date calculation functions and GraphQL execution)
- tests/fixtures/graphql_calendar.json (Mock contribution calendar fixture)
- .planning/phases/04-languages-streaks-metrics/04-RESEARCH.md (Section 7.1)
- .planning/phases/04-languages-streaks-metrics/04-PATTERNS.md (Section 3.1)
</read_first>

<action>
1. In `scripts/update_profile.py`, define `DEFAULT_STREAK_FIXTURES` with a dictionary containing `current_streak: 5`, `longest_streak: 14`, `total_contributions: 482`, and `standby: False`.
2. Implement `compute_streaks_from_calendar(contribution_days: list[dict], now_utc: datetime.datetime | None = None) -> tuple[int, int, int]` in `scripts/update_profile.py` per D-04, D-05, D-06:
   - Evaluates `now_utc` (defaulting to `datetime.datetime.now(datetime.timezone.utc)`).
   - Maps each day's ISO date string to `contributionCount` (int).
   - Computes `total_contributions` as the sum of all counts across the calendar.
   - Calculates historical `longest_streak` by scanning sorted calendar days chronologically.
   - Computes `current_streak` with today-grace-period per D-05:
     - If `today_utc` contributions > 0, streak starts today and counts backwards consecutive days.
     - If `today_utc` == 0 but `yesterday_utc` > 0, streak starts yesterday and counts backwards consecutive days (streak remains active).
     - If both `today_utc` == 0 and `yesterday_utc` == 0, `current_streak` is 0.
   - Returns `(current_streak, max(longest_streak, current_streak), total_contributions)`.
3. Implement `fetch_streak_telemetry(cache: dict, token: str | None = None) -> dict` in `scripts/update_profile.py` per D-22:
   - Tier 1: If `token` is present, queries GraphQL `viewer.contributionsCollection.contributionCalendar { totalContributions weeks { contributionDays { date contributionCount color } } }`, calls `compute_streaks_from_calendar()`, updates `cache["streak_metrics"]`, and returns dictionary with `current_streak`, `longest_streak`, `total_contributions`, `standby: (current_streak == 0)`.
   - Tier 2: On query error or token absence, checks `cache.get("streak_metrics")`; if valid, returns cached data.
   - Tier 3: Falls back to `DEFAULT_STREAK_FIXTURES`, logging `log_warn()`.
4. In `tests/test_metrics.py`, add unit tests:
   - `test_streak_calculation_active_today`: asserts streak includes today when today count > 0.
   - `test_streak_calculation_today_grace_period`: asserts streak does not break if yesterday count > 0 and today count == 0.
   - `test_streak_calculation_inactive_standby`: asserts streak resets to 0 if both today and yesterday counts == 0.
   - `test_longest_streak_historical_carry`: asserts longest streak carries previous run even after current streak breaks.
   - `test_fetch_streak_telemetry_offline_fallback`: asserts offline fallback returns cached data or default fixtures.
</action>
