## 4. Architecture Patterns

### Pattern 1: Standalone Vector SVG Generation with Strict XML Validation
- Matches established repo pattern in `generate_hero.py` and `generate_projects.py` [VERIFIED: `scripts/generate_projects.py` lines 203-284].
- SVG geometry conforms to 850px width standard (`viewBox="0 0 850 340"`).
- Strict XML validation using Python stdlib `ET.fromstring(svg_text)` ensures zero malformed tags or unclosed nodes can ever be written to disk.

### Pattern 2: Multi-Tier Resilient Telemetry Fallback
Every fetch function follows a 3-tier resolution strategy:
1. **Tier 1 (Live API with Token)**: Authenticated GraphQL/REST query with backoff and rate-limit checking.
2. **Tier 2 (Disk Cache Fallback)**: If network fails, API returns HTTP error, rate limits are hit, or no token is provided, load existing cached telemetry from `data/cache.json`.
3. **Tier 3 (Default Static Fixtures)**: If cache file is missing or corrupted, use verified default fixtures so build scripts never crash or exit non-zero.

```
       [ Token / Network Available? ]
                /           \
             (Yes)          (No)
              /               \
     [ GitHub API ]      [ data/cache.json ]
            |                    |
        (Success?)          (Has Data?)
        /       \             /       \
     (Yes)      (No)        (Yes)     (No)
       |          \           |         |
[ Update Cache ]   \          |         |
       \            +---------+         |
        \                     |         |
      [ Telemetry Data ] <----+         |
                                        v
                            [ Default Fixtures ]
```

### Pattern 3: Cross-Platform Vector Progress Tracks (SVG `<rect>` vs Unicode)
- **Constraint (D-07):** In prior implementations and general terminal art, Unicode progress blocks like `[████████░░]` suffer from platform-specific font advance widths. In macOS SFMono, Windows Consolas, and Linux Liberation Mono, `█` glyphs have varying aspect ratios, causing percentage columns to misalign horizontally.
- **Solution:** SVG vector `<rect>` tracks inside the terminal card:
  - Background track: `<rect x="540" y="{y - 9}" width="200" height="8" rx="3" fill="#21262d" />`
  - Filled track: `<rect x="540" y="{y - 9}" width="{fill_w}" height="8" rx="3" fill="{lang_color}" />`
  - Guaranteed pixel-perfect alignment across all browsers, mobile screens, and operating systems.

### Pattern 4: Surgical Markdown Anchor Injection
- Target file: `README.md`.
- Bounds: `<!-- METRICS:START -->` and `<!-- METRICS:END -->` [VERIFIED: `README.md` lines 24-25].
- Only replaces content strictly between the comment boundaries, keeping all other README sections untouched.
- Idempotent: If the generated replacement matches existing content, disk write is skipped and git status remains clean.

## 6. Common Pitfalls & Edge Cases

### Pitfall 1: Truncated / Missing `payload.commits` in GitHub Public Events
- **Root Cause:** GitHub implemented performance optimizations to the Public Activity Events API (`/users/{username}/events/public`) that trim nested commit summaries and payloads to minimize bandwidth [CITED: github.blog / StackOverflow grounding].
- **Impact:** Code that accesses `event["payload"]["commits"][0]["message"]` will raise `KeyError: 'commits'`.
- **Mitigation:**
  1. Primary strategy: Query GraphQL for commits across recently pushed repositories:
     `viewer.repositories(first: 8, orderBy: {field: PUSHED_AT, direction: DESC}) { nodes { defaultBranchRef { target { ... on Commit { history(first: 5) { nodes { oid messageHeadline committedDate url } } } } } } }`.
  2. Fallback strategy for REST: If using `/events/public`, safely check `payload.get("commits")`. If absent, extract the commit SHA from `payload.get("head")` and provide a fallback summary or query commit details.

### Pitfall 2: Streak Calculation UTC Timezone & Today-Grace-Period
- **Root Cause:** A developer pushing code at 23:30 UTC yesterday might run the profile updater at 08:00 UTC today before having pushed their first commit of the day. If the streak algorithm requires a commit strictly on `today_utc`, the streak will prematurely reset to 0!
- **Mitigation (D-05):**
  - Check `today_utc` contributions. If > 0, streak includes today.
  - If `today_utc` contributions == 0, check `yesterday_utc` contributions. If `yesterday_utc` > 0, the streak is still alive! The user has until 23:59:59 UTC to commit. Streak starts counting backwards from yesterday.
  - If both `today_utc` == 0 AND `yesterday_utc` == 0, then the streak is broken (`current_streak = 0`).

### Pitfall 3: Division by Zero in Language Percentages
- **Root Cause:** If a user account has empty repositories or only non-language assets, `total_valid_bytes` could be 0.
- **Mitigation:** Guard all percentage calculations: `(bytes / total_bytes * 100.0) if total_bytes > 0 else 0.0`.

### Pitfall 4: Bot Commits and Updater Feedback Loops
- **Root Cause:** Automated tools like Dependabot and GitHub Actions bots make commits to repositories. If the profile updater itself commits (`docs(update): ...`), without filtering, the "Recent Git Activity" stream will only show updater commits in an infinite visual feedback loop!
- **Mitigation (D-18):**
  - Filter out authors: `github-actions[bot]`, `dependabot[bot]`, `github-actions`, `dependabot`.
  - Filter out commit message prefixes: `docs(update):`, `chore(deps):`, `bump `.

### Pitfall 5: XML Character Entities in Commit Messages
- **Root Cause:** Developers often use commit conventions with angle brackets (e.g. `feat(<scope>): fix issue`). If rendered unescaped inside HTML `<pre><code>` or SVG text, the Markdown parser or XML validator crashes.
- **Mitigation:** Apply `html.escape(clamped_message)` for Markdown injection and `saxutils.escape()` for SVG text nodes.

### Pitfall 6: Shields.io / Komarev Badge Parameter Formatting
- **Root Cause:** Passing invalid color codes (e.g. including `#` without URL encoding `%23`) breaks badge rendering. Additionally, `komarev.com` does not parse `logo` or `logoColor` parameters [CITED: komarev.com search].
- **Mitigation:** Use raw 6-digit hex values without `#` (e.g. `color=3fb950&labelColor=161b22`) and keep parameters to standard supported fields (`username`, `color`, `labelColor`, `style`, `label`).

### 7.1 Streak Calculation with Today-Grace-Period
```python
def compute_streaks_from_calendar(
    contribution_days: list[dict],
    now_utc: datetime.datetime | None = None,
) -> tuple[int, int, int]:
    """
    Computes (current_streak, longest_streak, total_contributions) from contribution calendar days.
    Implements GitHub today-grace-period: if user committed yesterday, streak is alive even if
    they have not yet committed today.
    """
    if now_utc is None:
        now_utc = datetime.datetime.now(datetime.timezone.utc)
    today = now_utc.date()
    yesterday = today - datetime.timedelta(days=1)

    # Sort chronological
    sorted_days = sorted(contribution_days, key=lambda d: d["date"])
    day_map = {d["date"]: d.get("contributionCount", 0) for d in sorted_days}
    total_contributions = sum(day_map.values())

    # 1. Longest streak
    longest_streak = 0
    curr_run = 0
    for d in sorted_days:
        if d.get("contributionCount", 0) > 0:
            curr_run += 1
            if curr_run > longest_streak:
                longest_streak = curr_run
        else:
            curr_run = 0

    # 2. Current streak with grace period
    today_str = today.isoformat()
    yesterday_str = yesterday.isoformat()

    has_today = day_map.get(today_str, 0) > 0
    has_yesterday = day_map.get(yesterday_str, 0) > 0

    if not has_today and not has_yesterday:
        return 0, longest_streak, total_contributions

    start_date = today if has_today else yesterday
    current_streak = 0
    check_date = start_date

    while True:
        c_str = check_date.isoformat()
        if day_map.get(c_str, 0) > 0:
            current_streak += 1
            check_date -= datetime.timedelta(days=1)
        else:
            break

    return current_streak, max(longest_streak, current_streak), total_contributions
```

### 7.2 Language Aggregation & Percentage Calculation
```python
def aggregate_top_languages(
    repo_nodes: list[dict],
    ignore_list: list[str] | None = None,
) -> list[dict]:
    """
    Aggregates language byte counts across repositories, filters ignored prose languages,
    and returns top 5 languages + aggregated 'Other' row if remainder > 1%.
    """
    ignore_set = set(ignore_list or ["HTML", "CSS", "TeX", "Markdown"])
    lang_bytes: dict[str, int] = {}
    lang_colors: dict[str, str] = {}

    for repo in repo_nodes:
        lang_conn = repo.get("languages", {})
        edges = lang_conn.get("edges", [])
        for edge in edges:
            node = edge.get("node", {})
            name = node.get("name")
            size = edge.get("size", 0)
            color = node.get("color") or "#8b949e"

            if not name or name in ignore_set:
                continue

            lang_bytes[name] = lang_bytes.get(name, 0) + size
            lang_colors[name] = color

    total_bytes = sum(lang_bytes.values())
    if total_bytes == 0:
        return []

    sorted_langs = sorted(lang_bytes.items(), key=lambda x: x[1], reverse=True)
    top_5 = sorted_langs[:5]
    remainder = sorted_langs[5:]
    remainder_bytes = sum(b for _, b in remainder)

    result = []
    for name, b in top_5:
        pct = (b / total_bytes) * 100.0
        result.append({
            "name": name,
            "bytes": b,
            "color": lang_colors.get(name, "#8b949e"),
            "percentage": round(pct, 1),
        })

    if remainder_bytes > 0:
        rem_pct = (remainder_bytes / total_bytes) * 100.0
        if rem_pct >= 1.0:
            result.append({
                "name": "Other",
                "bytes": remainder_bytes,
                "color": "#8b949e",
                "percentage": round(rem_pct, 1),
            })

    return result
```

### 7.3 Recent Git Activity Stream Formatting
```python
import html

def format_git_activity_stream(activities: list[dict], now: datetime.datetime | None = None) -> str:
    """
    Renders terminal-styled <pre><code> git activity stream with clickable links.
    Clamps commit message to 50 characters with ellipsis.
    """
    lines = [
        '<div align="left">',
        "<pre><code>humam@workstation:~$ git log --graph --oneline -n 6",
    ]

    for item in activities[:6]:
        sha = item.get("sha", "")[:7]
        repo = item.get("repo", "repo")
        commit_url = item.get("url", f"https://github.com/humam-hossain/{repo}")
        repo_url = item.get("repo_url", f"https://github.com/humam-hossain/{repo}")
        raw_msg = item.get("message", "").strip().split("\n")[0]

        # Clamp to 50 chars with ellipsis
        if len(raw_msg) > 50:
            clamped = raw_msg[:47] + "..."
        else:
            clamped = raw_msg

        time_ago = item.get("time_ago", "recently")
        escaped_repo = html.escape(repo)
        escaped_msg = html.escape(clamped)

        lines.append(
            f'* <a href="{commit_url}">[{sha}]</a> '
            f'(<a href="{repo_url}">{escaped_repo}</a>) '
            f'{escaped_msg} ({time_ago})'
        )

    lines.append("</code></pre>")
    lines.append("</div>")
    return "\n".join(lines)
```

## 10. Security Domain (ASVS & STRIDE Analysis)

### ASVS Compliance (OWASP Application Security Verification Standard)
- **V5: Validation, Sanitization and Encoding:**
  - All repository names, commit messages, and URLs sourced from external APIs are treated as untrusted input.
  - Strict sanitization: `saxutils.escape()` for SVG XML nodes; `html.escape()` for Markdown `<pre><code>` blocks.
  - Prevents Cross-Site Scripting (XSS) or malformed SVG XML injection via crafted git commit messages.
- **V6: Cryptography and Token Handling:**
  - Authentication token priority checks `GITHUB_TOKEN` and `GH_TOKEN` securely.
  - Logging functions (`log_info`, `log_err`, `log_warn`) strictly prohibit logging authorization headers or token substrings.

### STRIDE Threat Modeling & Mitigations

| Threat | Description | Mitigation Strategy |
|--------|-------------|---------------------|
| **Spoofing** | Attacker creates spoofed commits to manipulate telemetry or inject arbitrary HTML. | Filter commits to authenticated user login (`author.user.login == "humam-hossain"`); escape all strings with `html.escape()`. |
| **Tampering** | Injected malicious payload in repository description or commit message (`<script>alert(1)</script>`). | Dual layer sanitization: `saxutils.escape()` in SVG and `html.escape()` in README HTML blocks. |
| **Repudiation** | Ambiguity in telemetry timestamps or source of truth. | Persistent timestamped caching in `data/cache.json` (`last_updated` UTC timestamps for every telemetry domain). |
| **Information Disclosure** | Token leaked through crash dumps or unhandled exceptions. | Generic error messaging without printing `urllib` headers; zero token echo in stdout/stderr. |
| **Denial of Service** | GitHub API rate limit exhaustion (HTTP 429/403) breaking CI/CD build. | Multi-tier fallback hierarchy: if rate limited, engine logs warning and gracefully falls back to `data/cache.json`. |
| **Elevation of Privilege** | Code execution via template evaluation. | Pure string formatting with stdlib; zero `eval()`, zero `exec()`, zero dynamic template engine execution. |
