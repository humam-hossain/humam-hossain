# Plan 01-01: Terminal Design Tokens, Test Infrastructure & Design System Documentation

## Executive Summary

Establish the foundational design system and test harness for the terminal-themed GitHub profile. Plan 01-01 establishes Wave 0 testing infrastructure (`tests/__init__.py`, `tests/test_tokens.py`), defines the centralized terminal design tokens in `config/terminal_theme.json` covering geometry, typography, and GitHub Dark ANSI colors, and authors the visual design contract documentation in `docs/DESIGN_SYSTEM.md`. This plan implements Requirement HERO-03 (design token system) and sets up automated validation gates for all subsequent execution steps.

---

## Threat Model (ASVS Level 1)

<threat_model>
### STRIDE Threat Register

| Threat ID | Category | Component | Description | Mitigation Strategy |
|-----------|----------|-----------|-------------|---------------------|
| T-01-01 | Tampering | `config/terminal_theme.json` | Malformed JSON or invalid hex strings cause downstream Python generator crashes or Camo proxy render errors. | Strict schema validation in `tests/test_tokens.py` enforcing `re.compile(r"^#[0-9a-fA-F]{6}$")` on all color tokens. |
| T-01-02 | Denial of Service | `config/terminal_theme.json` | Missing required geometric parameters (e.g. `viewBox`, `traffic_lights`, `ansi_strip`) causes `generate_hero.py` `KeyError`. | Schema tests verify presence of all mandatory top-level keys (`geometry`, `colors`, `typography`) and nested structures. |
| T-01-03 | Information Disclosure | `config/terminal_theme.json` | Accidental leak of confidential paths or secrets in theme config. | Configuration strictly contains static styling tokens; verified zero environment variables or credentials referenced. |
| T-01-04 | Supply Chain (SC) | Test Harness & Config | External dependency poisoning via third-party token loaders or test runners. | Zero external PyPI runtime dependencies; test suite uses pre-installed `pytest` and standard library `json`, `re`, `pathlib`. |
</threat_model>

<action>
Create `docs/DESIGN_SYSTEM.md` documenting:
1. Terminal Identity & Philosophy: Unix Neofetch CLI aesthetic embedded in a macOS terminal frame, dark theme only (opaque `#0d1117`).
2. 60-30-10 Color Architecture:
   - 60% Dominant: `#0d1117` console background canvas.
   - 30% Structural: `#161b22` header bar and badge backgrounds, `#30363d` 1px border.
   - 10% Accents: Cyan `#a5d6ff` (monogram & cursor), Amber `#ffa657` (telemetry keys), Green `#3fb950` / Red `#f85149` (LOC metrics), Blue `#58a6ff` (shell prompt).
3. ANSI 8-Color Diagnostic Strip specification (Black, Red, Green, Amber, Blue, Magenta, Cyan, White).
4. Typography & Monospace Font Stack (`ui-monospace, SFMono-Regular, Menlo, Consolas, "Fira Code", monospace`).
5. Window Chrome & Geometry Grid (`viewBox="0 0 850 380"`, traffic lights, clipPath corner isolation).
6. GitHub Camo Proxy Hardening (no foreignObject, no external font imports, XML entity escaping).
7. Downstream Contract: DOM ID reservation (`val-uptime`, `val-loc-add`, `val-loc-del`) for Phase 2 dynamic patching.
</action>
